# نور | NOOR

تطبيق تعليمي تفاعلي للأطفال والأسرة، يجمع التعلم الإسلامي المبسط مع تنمية المهارات والعادات الإيجابية والألعاب والإنجازات، ضمن تجربة تتكيف مع عمر المتعلم وملفه.

> **حالة المشروع:** مستودع NOOR هو مصدر التغييرات القابل للمراجعة. تُعرض حالة البناء والمراجعة من GitHub Actions وطلبات الدمج الحالية؛ لا تعتمد على وصف تاريخي ثابت للحالة.

## رؤية المنتج

نور مساحة تعلم آمنة ومحفزة تساعد الطفل على:
- بناء صلة محبة بالقرآن الكريم والعبادات والذكر.
- التعرف على السيرة النبوية والأنبياء والشخصيات الإسلامية.
- ممارسة الأخلاق والآداب في مواقف الحياة اليومية.
- تنمية القراءة واللغة والتفكير والمهارات الأساسية.
- التعلم باللعب والتحديات ومتابعة التقدم والإنجازات.
- التعلم وفق العمر والمرحلة والاهتمامات، لا وفق قوالب نمطية مرتبطة بالنوع.

## التدرج العمري

المواد الجديدة موزعة على ثلاث مراحل تجريبية:
- **3–5 سنوات:** الصورة والتكرار والأنشطة القصيرة بمرافقة ولي الأمر.
- **6–8 سنوات:** القراءة المبسطة والاختيار والترتيب والتطبيق العملي.
- **9–12 سنة:** الفهم والتفكير والبحث والمشروعات الصغيرة والمسؤولية الرقمية.

هذه حدود إرشادية للمحتوى، وليست تقييماً لقدرات الطفل. يمكن لولي الأمر اختيار مستوى أسهل أو أصعب حسب احتياج المتعلم.

## المحتوى المضاف في NOOR 1.5

- نقل ملفات المحتوى الـ67 من فرع المصدر الأصلي؛ 66 ملفًا مطابقة حرفيًا، وملف القرآن استُكمل إلى 114 سورة. أُضيفت 9 حزم NOOR تحريرية، وملف توثيق للمصحف، و22 ملفًا تكميليًا للدروس واختبارات المستوى؛ الإجمالي 99 ملف JSON.
- إضافة 9 مجموعات محتوى تحريرية جديدة، تضم **81 درساً/نشاطاً** (9 أنشطة في كل قسم، موزعة بالتساوي على ثلاث مراحل عمرية) موزعة على القرآن والصلاة والأذكار والأخلاق والسيرة والشخصيات والأنبياء والألعاب والإنجازات.
- ربط مجموعات المحتوى الجديدة بمكتبة نور، مع عرض الخطوات والأسئلة التفاعلية المتاحة في كل نشاط.
- فصل ألعاب NOOR التحريرية عن 27 تحديًا قديمًا، مع إظهار 254 بطاقة/عنصر و27 موقفًا تفاعليًا وخيارات الإجابة ومجموعات الفرز بدل إسقاطها أثناء قراءة JSON.
- نقل 172 أصلًا مرئيًا وصوتيًا من فرع المصدر الأصلي المثبت: 161 رسمة WebP، و6 مؤثرات WAV، وأنشودة MP3 واحدة، ومقدمة MP4 واحدة، وأيقونتان قديمتان محفوظتان دون استبدال شعار NOOR الجديد.
- ربط المؤثرات داخل بطاقات الأسئلة، وإتاحة الأنشودة الأصلية والمقدمة السينمائية من مكتبة التطبيق.
- ربط بنك العبارات الصوتية (3,736 عبارة) بمكتبة نطق عربية عبر TTS، وإضافة زر استماع داخل المواد التعليمية.
- إظهار دروس القرآن المناسبة للعمر بشكل منفصل عن فهرس السور الكامل، وإتاحة مراجعة مهارات قصيرة من ثلاثة بنوك عمرية (36 سؤالًا) مع تنبيه واضح أن المحتوى قيد المراجعة وليس تشخيصًا أو اعتمادًا شرعيًا.
- إضافة مشغل تلاوة متتابعة للقرآن باستخدام ملفات مشاري العفاسي من EveryAyah؛ ملفات التلاوة المحلية لم تكن موجودة في مجلدات المصدر quran/voice، لذلك التلاوة تُبث عبر الإنترنت.
- الإبقاء على الملفات الأصلية المنقولة لأغراض المراجعة والتتبع.
- إضافة هوية كتاب مفتوح وهلال ونجمة، وملف شعار SVG وأيقونة Android محدثة.

الملفات التحريرية الجديدة موجودة في:
`legacy_content/assets/content/noor_*.json`

## مبادئ الجودة والمراجعة

- لا تُنسب آية أو حديث أو فضل تعبدي دون مرجع واضح يمكن مراجعته.
- مواد القرآن تشير إلى السورة والآيات، ويجب أن يكون نص المصحف والتلاوة من مصدر موثوق.
- موضوعات الفقه والعبادات تعريفية ومبسطة، ويُرجع في تفاصيل الأحكام إلى ولي الأمر أو معلم مؤهل والمصدر المعتمد للأسرة.
- لا تستخدم الأنشطة التخويف أو الإحراج أو مقارنة الأطفال بعضهم ببعض.
- لا يُطلب من الطفل نشر اسمه أو صورته أو موقعه أو أي بيانات خاصة.
- يراعى اختلاف سرعة التعلم والاحتياجات، مع إشراف بالغ في الأنشطة العملية.
- كل درس تحريري جديد يحمل `content_verified: false` و`review_status: pending` و`citation_status: needs_review` حتى تتم مراجعته بشريًا. لا تُعرض المراجع العامة أو غير المكتملة باعتبارها توثيقًا نهائيًا. مدقق CI يتحقق من الحقول والاتساق، لكنه لا يمنح اعتمادًا شرعيًا ولا يثبت صحة المرجع.

## بنية المشروع

- `NOOR_Source.zip`: أرشيف مصدر التطبيق الأساسي المستخدم في خط بناء Android.
- `.github/noor-overlay.tar.b64`: طبقة الهوية البصرية والواجهات والأصول التي تُفك فوق المشروع الأساسي.
- `.github/scripts/`: جلب نص Tanzil الكامل، واستيراد الأصول المرئية والصوتية الأصلية مع التحقق من Git blob SHA، وفحص نقاط الصوت، والتحقق من سلامة المحتوى.
- `.github/workflows/build.yml`: سير عمل تركيب الطبقات والتحليل والاختبارات وبناء APK.
- `legacy_content/assets/content/`: ملفات JSON المنقولة والمجموعات التحريرية الجديدة.
- `noor_upgrade/lib/data/content/legacy_content.dart`: قارئ محتوى المكتبة.
- `noor_upgrade/lib/features/home/legacy_content_screen.dart`: شاشة مكتبة نور.
- `noor_upgrade/patch_noor.py`: تركيب المسارات والتحديثات على مشروع Flutter الأساسي.

**سبب وجود ZIP بجوار الملفات:** هذا ترتيب بناء طبقي مقصود؛ يُفك الأرشيف أولًا، ثم تُطبّق طبقة الواجهات والهوية، ثم تُنسخ بيانات المحتوى وتحديثات Dart. الملفات المجاورة ليست نسخ APK مكررة، بل مدخلات لازمة لإنتاج التطبيق. سيظل الأرشيف محفوظًا كقاعدة إلى أن يُحوّل المستودع إلى هيكل Flutter تقليدي بجذر واحد.

يُجلب نص Tanzil أثناء البناء، ويُتحقق من تسلسل 114 سورة و6,236 آية، ثم يُحفظ داخل المستودع وحزمة التطبيق. كما تُجلب الأصول الـ172 من فرع المصدر المثبت وتُراجع بصمة كل ملف قبل إضافتها. يُعرض نص القرآن دون اتصال، بينما التلاوة تحتاج إلى الإنترنت. الأنشودة والمؤثرات والمقدمة السينمائية محلية؛ وبنك العبارات يُنطق بمحرك TTS ولا يمثل تسجيلات MP3 أصلية.

## البناء والتحقق

يتطلب البناء Flutter stable وAndroid SDK وJava 17، بالإضافة إلى أسرار توقيع Android المضبوطة في إعدادات GitHub Actions.

للبناء المحلي داخل مشروع Flutter المستخرج:

```bash
flutter pub get
dart format lib test
flutter analyze
flutter test
flutter build apk --release
```

ينتج ملف Android:
`build/app/outputs/flutter-apk/app-release.apk`

سير GitHub Actions يجلب نص القرآن الكامل من Tanzil، ويستورد 172 أصلًا مرئيًا وصوتيًا مع التحقق من بصماتها، ويفحص ثلاثة مسارات تلاوة نموذجية، ويتحقق من أعداد السور والآيات وبنوك الألعاب والصوتيات، ثم ينفذ مدقق JSON وتحليل Flutter واختبارات parser وبناء APK. بناءات Pull Request لا تستخدم أسرار الإصدار؛ تستخدم مفتاح CI مؤقتًا للاختبار فقط. مفتاح الإصدار الحقيقي والتحقق من توقيعه يقتصران على `main` أو الوسوم (tags). الإصدار المستهدف APK فقط، وليس Android App Bundle (AAB).

## خارطة الطريق

1. توسيع وحدات كل قسم إلى وحدات تعليمية ودروس قصيرة ومراجعات واختبارات.
2. مراجعة النصوص الدينية ومراجعها بواسطة مختصين.
3. إضافة تسجيلات صوتية مرخصة ورسوم توضيحية أصلية مع نصوص بديلة.
4. ربط الأنشطة بنظام التقدم والنجوم والشارات دون مكافآت ضاغطة.
5. تطوير اختبارات تحديد المستوى ومسارات تعلم قابلة للتخصيص.
6. تحسين لوحة ولي الأمر وتقارير التقدم وإعدادات وقت الشاشة.
7. توسيع اختبارات parser لتغطية بقية صيغ البيانات القديمة، وإضافة مراجعة بشرية موثقة للمراجع قبل اعتماد أي محتوى ديني.
